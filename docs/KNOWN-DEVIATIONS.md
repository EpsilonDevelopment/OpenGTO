# Known Deviations From The Official Artifact

The restored tree compiles and reproduces the official class set, but it is a reconstruction, not
the original source. Known differences:

1. **Anonymous class names (resolved 2026-09-23).** The seven Kotlin-generated anonymous classes
   (`CustomBuilder$buildAndInit$1`, `RootBuilder$buildAndInit$1`,
   `FlexibleContainerDslKt$rootFresh$FreshWidgetGroup`,
   `FlexibleContainerExtendedKt$vBoxThreeColumn$2`, `FlexibleStandardWidgetKt$button$button$1`,
   `FlexibleStandardWidgetKt$field$field$1`, `FlexibleStandardWidgetKt$iconButton$button$1`) used to
   be Java files named `X$1` … `X$3`. With the Kotlin sources restored the Kotlin compiler derives
   the official names again, and no `$`-named Java file remains in `src/main/java`. A full
   class-name diff against the official jar has not been re-run since the restoration.
2. **Extra anonymous classes (resolved 2026-09-23).** `MainLogic$1` and `RecipeScreenMixin$1` — the
   anonymous classes the Java reconstruction materialised for Kotlin lambdas — no longer exist;
   `src/main/java` contains no `$`-named source at all.
3. **Kotlin-origin classes (resolved).** The 37 Kotlin-origin classes are restored as 13 real
   Kotlin files under `src/main/kotlin/com/gtolib/` (2026-09-23), so their extension functions,
   default/named arguments and lambda-with-receiver signatures — and the anonymous-class names the
   Kotlin compiler derives from them — come back by construction instead of being approximated.
   The Vineflower Java view in `docs/kotlin-source-reference/` is retained as reference only.
4. **Manifest.** The official protected jar inherits GTOCore's manifest
   (`Specification-Title: GTOdyssey`, `MixinConfigs: gtocore.mixins.json,gtolib.mixins.json`, seal
   attributes). This project writes its own (`GTOLib`, `MixinConfigs: gtolib.mixins.json`).
5. **Pipeline artifacts absent by design:** `gtocore.refmap.json`,
   `META-INF/gtocore-forge-1.20.1.kotlin_module`, the 675 `native0/**/*.prod.bin` sealed payloads,
   and the seal/NTPT manifest attributes.
6. **No `gtolib.refmap.json` in `src/main/resources`.** It is generated by the Mixin annotation
   processor, as in the official pipeline. Keeping a copy in the source set makes `:jar` fail with
   a duplicate-entry error.
7. **Cosmetic loss.** Original comments, Javadoc, local variable names, parameter names in some
   bodies, and source line numbers are not recoverable; Vineflower labels and `varNNN` temporaries
   remain where the bytecode gave no name.
8. **Not runtime-verified.** The tree is verified by clean compilation and class-set comparison
   against the official jar. It has not been loaded into the client (the sealed official jar is
   what the client runs).
